## 팀 기반 운영 안전성 수정 3차
- 병렬 리뷰 결과를 통합해 production 데이터 경로를 fail-closed로 강화했다. `APP_DATA_DIR`는 production에서 필수/절대경로/웹 루트 외부여야 하며, `CONTENT_PATH`/`COMMENTS_PATH`/`AUTH_PATH`도 `APP_DATA_DIR` 내부로 제한했다.
- `/api/content` 공개 payload를 중첩 allowlist serializer로 바꿔 `detail`, `blocks`, `links`, `media`, list item 내부의 임의 admin/private 필드가 노출되지 않게 했다.
- Node 배포 산출물을 staging manifest 기반 rsync로 전환해 기존 운영 루트의 stale `deploy/`, `scripts/`, `test/`, `.env`, `data/content.json`도 제거되도록 했다. `DRY_RUN=1`은 대상과 `data/`가 이미 있을 때만 동작하게 유지했다.
- static nginx conf에 소스/운영 도구/데이터 경로 deny, CSP Report-Only, location별 보안 헤더 반복, assets `immutable` 제거를 적용했다.
- systemd unit에 `/etc/thecistus-homepage.env`, `SKIP_DOTENV=1`, 절대 `ExecStart`, read-only 코드/전용 data 쓰기 경로와 hardening 옵션을 추가했다.
- legacy static nginx install을 `ALLOW_LEGACY_STATIC_INSTALL=1` 없이는 중단되도록 가드했다.
- env/smoke/preflight/deploy 보안 테스트와 운영 문서를 새 배포 산출물 정책에 맞게 갱신했다.
- 배포, systemd/nginx 적용, 서비스 재시작, 외부 도메인 smoke는 실행하지 않았다.
